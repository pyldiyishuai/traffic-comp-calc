# 交通事故赔偿计算器 · 技术方案

---

## 一、产品定位

### 用户是谁

| 画像 | 场景 | 核心诉求 |
|---|---|---|
| 刚出事故的人 | 对方说「私了给你两万」 | 到底该拿多少 |
| 已出院在谈赔偿 | 保险公司报了价 | 报价合不合理 |
| 准备做伤残鉴定 | 不知道值不值得做 | 十级能多拿多少 |
| 家属代为处理 | 不懂法律术语 | 有哪些项目 |

### 为什么这个需求值钱

1. **决策金额极大**：单案 10 万–100 万，用户对准确性要求高
2. **信息严重不对称**：普通人不知道有 11 项，只知道医疗费和误工费
3. **法律服务 CPC 极高**：律师、法律咨询的获客成本在 ¥50–500/条
4. **复购率低但单价极高**：一辈子用一次，但那一次就是几万块

**这是十个项目里商业价值最高的一个。**

## 二、核心算法

### 2.1 赔偿项目结构

```
是否构成伤残
├── 否 → 医疗费、误工费、护理费、营养费、住院伙食补助、
│        交通费、后续治疗费、财产损失
└── 是 → 上述全部 +
         残疾赔偿金、被扶养人生活费、精神损害抚慰金
```

**后三项才是大头。** 十级伤残、40 岁、全国平均就是 11.3 万。

### 2.2 残疾赔偿金

```
赔偿金 = 城镇居民人均可支配收入 × 赔偿年限 × 伤残系数
```

**赔偿年限**（`compYears`）：

```
age < 60  → 20
age < 75  → 20 − (age − 60)
age ≥ 75  → 5
```

注意 60 岁本身仍是 20 年（`20 − 0`），这是最容易写错的地方。

**伤残系数**：

```
1 级 → 1.0    6 级 → 0.5
2 级 → 0.9    7 级 → 0.4
3 级 → 0.8    8 级 → 0.3
4 级 → 0.7    9 级 → 0.2
5 级 → 0.6    10 级 → 0.1
```

### 2.3 被扶养人生活费

```
消费支出 × 扶养年限 × 伤残系数 × 被扶养人数 ÷ 扶养义务人数
```

- 扶养年限上限 20 年（未成年人算到 18 岁）
- 扶养义务人数：有几个法定扶养人。父母有两个子女 → 2

**这一项最容易被漏掉。** 有未成年子女或丧失劳动能力的父母就能主张。

### 2.4 交强险拆分

这是本工具最容易做错的地方。三个限额**分别计算**：

```
医疗类：医疗费 + 营养费 + 住院伙食 + 后续治疗费 → 限额 18,000
死亡伤残类：误工 + 护理 + 交通 + 残疾赔偿金 + 被扶养人 + 精神抚慰金 → 限额 180,000
财产类：财产损失 → 限额 2,000
```

```
交强险赔付 = min(医疗类, 18000) + min(死亡伤残类, 180000) + min(财产类, 2000)
超出部分   = (各类 − 各自限额) 之和
实际可得   = 交强险赔付 + 超出部分 × 责任比例
```

**关键点**：交强险限额内不看责任比例。对方只有 70% 责任，
交强险那部分仍然全额赔。

## 三、数据维护

`data/comp-rules.js` 的 `regions` 是唯一需要定期更新的部分。

| 字段 | 含义 | 更新频率 |
|---|---|---|
| `income` | 城镇居民人均可支配收入 | 每年 1–3 月 |
| `consume` | 城镇居民人均消费支出 | 每年 1–3 月 |
| `meal` | 住院伙食补助标准 | 较少变动 |
| `nursing` | 当地护工日工资 | 每 2–3 年 |

数据源：各省统计局年度统计公报、国民经济和社会发展统计公报。

**建议做成配置文件或远程 JSON**，这样不用改代码就能更新。

## 四、扩展点

### 4.1 死亡赔偿（最高优先）

**场景**：交通事故致死，家属需要知道能赔多少。

**项目**：
- 死亡赔偿金 = 城镇居民人均可支配收入 × 20 年（同残疾赔偿金的年限规则，但不乘系数）
- 丧葬费 = 上年度职工月平均工资 × 6 个月
- 被扶养人生活费
- 精神损害抚慰金（通常更高）

**改哪里**：`core/comp.js` 加一个 `buildDeathResult`，复用现有年限与基数逻辑。

### 4.2 律师咨询线索（核心变现）

**已有**：`APP.FEATURES.lawyerLead` 开关、`#leadBox` 结构、`integrations/api.js` 的 `leadSubmit`。

**触发条件**：`total > 100000` 时才显示。这个阈值很关键——
小额案件转化率极低，还会拉低整体质量。

**表单字段**：联系方式、事故时间、是否已做鉴定、是否已签协议。
**合规**：必须有隐私政策、明示用途、提供退出方式。

### 4.3 多年度分段计算

**场景**：事故发生在 2023 年，2025 年才判决。
**规则**：一般按「一审法庭辩论终结时的上一年度」标准计算，
但个别项目（如误工费）要看实际发生年度。
**改哪里**：`regions` 改成按年份嵌套的结构。

### 4.4 导出赔偿清单

**用途**：打印出来和保险公司谈，或者交给律师。
**方案**：`@media print` 样式表 + `window.print()`，比引 PDF 库省事。
**注意**：打印样式要隐藏广告、导航、悬浮条、FAQ。

### 4.5 办案流程时间线

**场景**：用户不知道下一步该做什么。
**内容**：报警→就医→责任认定→伤残鉴定→协商→诉讼，每步的时间节点和注意事项。
**价值**：极强的内容属性，适合做独立 SEO 页面。

### 4.6 计算器 vs 判例库

**长期方向**：接入公开裁判文书数据，展示「类似案件实际判了多少」。
**价值**：这是律师都在用的数据，做成免费工具是降维打击。
**难点**：数据获取与清洗成本高。

## 五、SEO 策略

### 5.1 关键词结构

```
核心：交通事故赔偿计算器
  ├── 项目词：残疾赔偿金计算 / 被扶养人生活费 / 精神损害抚慰金
  ├── 等级词：十级伤残赔多少 / 九级伤残赔偿标准 / 一级伤残
  ├── 流程词：伤残鉴定什么时候做 / 交通事故起诉流程
  └── 长尾词：车祸十级伤残能赔多少钱 / 农村户口按城镇标准
```

**「X 级伤残赔多少」是最强的一组**：搜索量大、意图精确、
竞争相对小（多数是律所页面，工具型页面很少）。

### 5.2 独立页面规划

| 页面 | 关键词 | 价值 |
|---|---|---|
| `/shiji` | 十级伤残赔多少 | ★★★ 搜索量最大 |
| `/jianding` | 伤残鉴定什么时候做 | ★★★ 流程刚需 |
| `/beifuyang` | 被扶养人生活费怎么算 | ★★☆ 差异化 |
| `/jiaotongqiangxian` | 交强险赔偿限额 | ★★★ |
| `/nongcun` | 农村户口按城镇标准赔 | ★★☆ 纠错型内容 |
| `/hunyin` | 死亡赔偿标准 | ★★★ 单价最高 |

### 5.3 内容策略

这个赛道的内容比工具更容易获客，因为用户搜的是「怎么办」而不是「算一下」。

**最值得写的三篇**：
1. 《十级伤残到底能赔多少钱（附 31 省对照表）》
2. 《伤残鉴定什么时候做？做早了可能白做》
3. 《保险公司压价的 5 种常见说法，怎么反驳》

## 六、变现

| 方式 | 单价 | 优先级 |
|---|---|---|
| **律师咨询线索** | ¥50–500/条 | ★★★ |
| 法律服务平台 CPS | 分成 20%–40% | ★★☆ |
| 司法鉴定机构导流 | ¥100–300/条 | ★★☆ |
| 通用联盟广告 | CPC ¥0.3–2 | ★☆☆ |

**线索质量比数量重要。** 一个「已做鉴定、金额 20 万、还没签协议」的线索
价值远超一百个随便算算的流量。

所以：**只在金额超过 10 万时展示咨询入口**，这是提高转化率的关键设计。

## 七、监控指标

| 指标 | 意义 |
|---|---|
| 计算完成率 | 15 个字段较多，目标 >50% |
| 伤残等级分布 | 判断用户伤情，决定内容方向 |
| 地区分布 | 决定优先做哪几个省的数据精度 |
| 平均赔偿金额 | 「平均每案 18 万」是很好的内容素材 |
| 有被扶养人的比例 | 这项最容易被漏，比例低说明用户不懂 |
| 线索转化率 | 直接决定收入 |

## 八、已知坑

### 坑 1：伤残系数方向搞反

`level * 0.1` 是错的。1 级最重应该是 100%。
正确：`(11 - level) / 10`。

### 坑 2：60 岁的边界

`age < 60 → 20`，`age = 60` 时 `20 - 0 = 20`。
两个分支都给 20 年，不是笔误。

### 坑 3：交强险三个限额不能合并

医疗 1.8 万 + 死亡伤残 18 万 + 财产 2000，是三个独立的池子。
写成一个 19.8 万的总额会算错。

### 坑 4：chips 与 hidden input 不同步

先用 chips 选等级（写进 hidden input），
再用 URL 参数恢复时，**必须反向同步 chips 的高亮**，
否则界面显示的是「十级」而实际算的是「一级」。

修法：在 `updateHints()` 里根据当前值刷新所有 chip 的 `is-on`。

### 坑 5：删了函数但忘了删导出

`analytics.js` 里删掉 `bucket` 函数，导出对象里还留着 `bucket: bucket`，
直接报 `ReferenceError`。改用新函数名时要全局搜一遍。

### 坑 6：金额格式化不能统一用「万」

赔偿清单里要显示精确到元的金额（108,376），
用「10.8 万」会让人怀疑准确性。清单用 `moneyFree`，主数字用「万」。
